# 01 — ความเป็นไปได้ & ข้อจำกัดของ LINE OA ในกลุ่ม

## 1. ทำได้ไหม — ได้

LINE Messaging API รองรับให้ OA (bot) อยู่ในกลุ่มแชทปกติได้

- ต้องเปิด **"Allow bot to join group chats"** ในแท็บ *Messaging API* ของ LINE Developers Console (ค่าเริ่มต้นปิด)
- เมื่อเปิดแล้ว สมาชิกในกลุ่มเชิญ OA เข้ากลุ่มได้เหมือนเชิญเพื่อน
- bot ได้รับ webhook ของข้อความในกลุ่ม เหมือนแชท 1:1 โดย `source` จะมี `groupId` และ `userId` ของคนส่ง
- **1 กลุ่มมี OA ได้ทีละ 1 ตัวเท่านั้น**

### Event ที่เราจะได้ และใช้ทำอะไร

| Event / Message | ใช้ทำอะไร |
|---|---|
| `message` → `text` | ตัวรายงาน (หน้างาน / ช่าง / โทร / รายละเอียด / ตามต่อ) |
| `message` → `image` (+ `imageSet` ถ้าส่งหลายรูปพร้อมกัน) | รูปหน้างาน → ดาวน์โหลดเก็บ R2 |
| `message` → `location` | lat/lng + address (มี ตำบล/อำเภอ/จังหวัด ในข้อความ address) |
| `message` → `sticker` | ข้าม (แต่เก็บ raw ไว้) |
| `quotedMessageId` ใน text | เซลล์กด "ตอบกลับ" ข้อความเดิม → ใช้ผูก follow-up กับงานเดิมได้แม่นที่สุด |
| `unsend` | เซลล์ยกเลิกข้อความ → ลบ/ซ่อนรายงานนั้น (ในภาพตัวอย่างมี "ยกเลิกข้อความ" จริง) |
| `edit` (มีเฉพาะในกลุ่ม) | เซลล์แก้ข้อความ → re-parse รายงานนั้นใหม่ *(ตรวจ payload จริงตอน implement)* |
| `join` / `leave` / `memberJoined` / `memberLeft` | บันทึกกลุ่ม, เซลล์เข้า/ออก |

## 2. ข้อจำกัดที่ต้องรู้

| ข้อจำกัด | ผลกระทบ / วิธีรับมือ |
|---|---|
| bot **ไม่เห็นข้อความก่อนเข้ากลุ่ม** | ข้อมูลเก่าใช้วิธี **import จาก Excel** ที่ทีมใช้อยู่ (ชีทรูป 03) |
| รูป/วิดีโอที่ผู้ใช้ส่ง **LINE ลบอัตโนมัติหลังช่วงเวลาหนึ่ง** | ต้องดาวน์โหลดผ่าน `GET api-data.line.me/v2/bot/message/{id}/content` ทันทีที่ได้ webhook แล้วเก็บ R2 |
| API ดึงรายชื่อสมาชิกทั้งกลุ่ม (member IDs) ใช้ได้เฉพาะ **verified/premium account** | ไม่จำเป็น — ได้ `userId` จากทุกข้อความที่ส่งอยู่แล้ว + ดึงชื่อด้วย *Get group member profile* แล้วให้แอดมินผูก userId ↔ ชื่อเซลล์ |
| ถ้าผู้ใช้ไม่ยินยอมให้ข้อมูลโปรไฟล์ webhook อาจไม่มี `userId` | กรณีหายาก → เข้าคิวรอตรวจ |
| Webhook ไม่การันตี 100% และอาจส่งซ้ำ/สลับลำดับ | เปิด **Webhook redelivery**, กันซ้ำด้วย `webhookEventId`, เรียงด้วย `timestamp` |
| ต้องตอบ 2xx เร็ว | handler แค่ verify + บันทึก raw + enqueue แล้วตอบ 200 ทันที งานหนักไปทำใน worker |
| ข้อความที่ quote — API ไม่ให้เนื้อหาข้อความที่ถูก quote | ไม่เป็นปัญหา เพราะเรามี `messageId` → รายงานเดิมใน DB ของเราอยู่แล้ว |
| ประกาศกลุ่ม (announcement), โน้ต, อัลบั้ม | ไม่ได้มาเป็น message event ปกติ — แนะนำให้เซลล์ส่งรูปเป็นข้อความธรรมดา |

## 3. ค่าใช้จ่ายข้อความ (สำคัญกับเรื่องแจ้งเตือน)

- **รับ webhook = ฟรี ไม่จำกัด**
- **Reply message (ตอบกลับด้วย replyToken) = ฟรี ไม่นับโควต้า**
- **Push message = นับโควต้า** และ **ถ้า push เข้ากลุ่ม นับตามจำนวนคนในกลุ่ม** (กลุ่ม 16 คน push 1 ครั้ง = 16 ข้อความ)

แพ็กเกจ LINE OA ไทย (ราคาไม่รวม VAT, ตรวจล่าสุด ก.ย. 2569 — ควรเช็กหน้าราคา LINE อีกครั้งก่อนเสนอลูกค้า):

| แพ็กเกจ | ราคา/เดือน | ข้อความ/เดือน |
|---|---|---|
| Free | 0 | 300 |
| Basic | 1,280 บาท | 15,000 |
| Pro | 1,780 บาท | 35,000 |

**คำนวณ:** สรุป "งานที่ต้องตามวันนี้" push เข้ากลุ่มทุกวันทำงาน ≈ 22 × 16 = 352 ข้อความ → **เกิน Free**

ทางเลือกแจ้งเตือน (ดูรายละเอียดใน `02`):
1. **ใช้ reply ฟรี** — bot ตอบยืนยันรายงานพร้อมแนบ "งานค้างที่ต้องตามวันนี้ของคุณ X งาน" (ไม่เสียโควต้า)
2. **สรุปรายสัปดาห์** push เข้ากลุ่ม 1 ครั้ง/สัปดาห์ ≈ 4 × 16 = 64 ข้อความ → อยู่ใน Free
3. **Dashboard** ให้หัวหน้า/น้าอรดูรายการครบกำหนด (ไม่ใช้โควต้าเลย)
4. ถ้าลูกค้าอยากได้แจ้งเตือนรายวัน/รายคน → อัปเกรด **Basic 1,280 บาท/เดือน**

## 4. OA Free ที่บริษัทมีอยู่ — ใช้ได้ไหม หรือควรเปิดใหม่

**ใช้ได้ในทางเทคนิค** แต่ **แนะนำเปิด OA ใหม่แยก (Free)** เพราะ:

| ประเด็น | ใช้ OA เดิม | เปิด OA ใหม่ (แนะนำ) |
|---|---|---|
| ชื่อ/รูปที่โผล่ในกลุ่มเซลล์ | เป็นแบรนด์หน้าร้านที่คุยกับลูกค้า | ตั้งชื่อเฉพาะ เช่น "UP Sales Bot" |
| Webhook | ข้อความ **ลูกค้าทั่วไป** ที่ทักร้านจะไหลมาที่เซิร์ฟเวอร์เราด้วย (ต้องกรองทิ้ง และเกี่ยวกับ PDPA) | มีแต่ข้อมูลกลุ่มเซลล์ |
| Auto-reply / ข้อความต้อนรับ ที่ตั้งไว้ | อาจเด้งเข้ากลุ่มเซลล์ / ต้องไปปิด กระทบงานหน้าร้าน | ปิดได้เต็มที่ |
| โควต้าข้อความ | แชร์กับ broadcast การตลาดของร้าน | แยกกัน |
| ความเสี่ยง | ตั้งค่าผิดกระทบลูกค้าจริง | ทดลอง/ปิด/เปิดได้อิสระ |

**คำตอบที่ส่งน้าอรได้:** "ใช้แบบ Free ได้ครับ แต่แนะนำเปิด OA ใหม่อีกตัว (ฟรีเหมือนกัน) ใช้เฉพาะเก็บข้อมูลกลุ่มเซลล์ จะได้ไม่ปนกับ OA ที่คุยกับลูกค้า ไม่กระทบระบบเดิมครับ"

**ความเป็นเจ้าของ:** ให้บริษัทเป็นคนสร้าง OA ด้วย LINE Business ID ของบริษัท แล้วเพิ่มเราเป็น Admin ของ OA + Provider ใน Developers Console — ข้อมูล/บัญชีเป็นของลูกค้า

## 5. ข้อควรระวังด้าน PDPA / ความโปร่งใส

- แจ้งเซลล์ในกลุ่มว่ามี bot บันทึกข้อความเพื่อทำรายงาน (bot อยู่ในกลุ่มเห็นชื่อชัดเจนอยู่แล้ว)
- ข้อมูลลูกค้า (ชื่อ/เบอร์ช่าง/เจ้าของบ้าน) เป็นข้อมูลส่วนบุคคล → จำกัดสิทธิ์เข้าถึง dashboard, ใช้ HTTPS, R2 bucket ไม่เปิด public ทั้ง bucket (ใช้ presigned URL)
