# 06 — สิ่งที่ต้องเตรียม + คำถามลูกค้า + แผนแบ่งเฟส

## A. ฝั่งลูกค้า (UP Steel / น้าอร) ต้องทำ/ให้ข้อมูล

- [ ] **สร้าง LINE OA ใหม่ (Free)** ด้วย LINE Business ID ของบริษัท ตั้งชื่อเช่น "UP Sales Bot" + รูปโปรไฟล์
- [ ] เพิ่ม Notz เป็น **Admin** ของ OA และเป็น member ของ **Provider** ใน LINE Developers Console
- [ ] รายชื่อเซลล์: ชื่อเล่น / ชื่อในไลน์ / พื้นที่รับผิดชอบ (อำเภอ)
- [ ] ไฟล์ **Excel ติดตามงานเดิม** (ชีทในรูป 03) สำหรับ import
- [ ] แจ้งเซลล์ในกลุ่มว่าจะมี bot เข้ามาบันทึกรายงาน (PDPA / ความโปร่งใส)
- [ ] อนุมัติ template ใหม่ (เพิ่ม ลูกค้า / ผู้ตัดสินใจ / ขั้นตอน / คาดสั่ง / สถานะ)

## B. คำถามที่ต้องถามน้าอร (ส่งได้เลย)

1. ให้ bot **ตอบยืนยันในกลุ่ม** ทุกครั้งที่บันทึก ได้ไหม หรือให้ตอบเฉพาะตอนข้อมูลไม่ครบ/ผิด
2. รับการเพิ่มบรรทัดใน template ได้ไหม (ลูกค้า, ผู้ตัดสินใจ, ขั้นตอน, คาดสั่ง, สถานะ) — ไม่บังคับใส่ทุกบรรทัด
3. ตอน follow-up ให้เซลล์ **กด "ตอบกลับ" ข้อความเดิม** ได้ไหม (ช่วยให้ข้อมูลไม่ซ้ำ แม่นที่สุด)
4. คำสถานะที่ใช้จริงมีอะไรบ้าง (ตามต่อ / จบได้ / จบที่อื่น / ยกเลิก / อื่น ๆ) และ **รายการสาเหตุจบที่อื่น** ที่เจอบ่อย + ชื่อคู่แข่ง (เช่น "กระทิง")
5. "จำนวนการวิ่งงาน" นับทุกครั้งที่รายงาน หรือนับหน้างานไม่ซ้ำ
6. หน้างานเดียวกันถ้าเซลล์ 2 คนเจอ — นับเป็นของใคร
7. ใครจะดูรายงาน/dashboard (กี่คน) ต้องการดูบนมือถือหรือคอม
8. การแจ้งเตือนวันต้องตาม: พอใจแบบสรุปรายสัปดาห์ในกลุ่ม + dashboard (ฟรี) หรืออยากได้รายวัน (ต้องอัป OA เป็น Basic 1,280 บาท/เดือน)
9. มีกลุ่มเซลล์มากกว่า 1 กลุ่มไหม (แยกทีม/แยกจังหวัด)
10. ต้องการยอดขาย/มูลค่างานในรายงานด้วยไหม

## D. แผนแบ่งเฟส (ที่แจ้งลูกค้าไว้ ~1 สัปดาห์ = เฟส 1)

### เฟส 1 — Capture & Parse (≈ 1 สัปดาห์)
- โปรเจกต์ Go Fiber + docker-compose + tunnel
- Webhook + signature + raw events + dedupe + worker
- ดาวน์โหลดรูป → R2, location
- Bundler + reportparser (rule-based) + test จากข้อความจริง
- Site/Report + รหัสงาน + matching ข้อ 1–4 (quote/code/phone/geo)
- Bot reply ยืนยัน
- **Export Excel** ตามคอลัมน์เดิม → ลูกค้าเห็นผลทันที
- Import Excel เดิม

### เฟส 2 — Admin Dashboard (≈ 1–2 สัปดาห์)
- Login, รายการหน้างาน, timeline + รูป + แผนที่
- คิวรอตรวจ (link/create/ignore), merge site
- จัดการเซลล์ / ผูก userId

### เฟส 3 — KPI & Reminder (≈ 1 สัปดาห์)
- Analytics: รายวัน/เดือน/ปี, ต่อเซลล์, ต่อพื้นที่, สาเหตุจบที่อื่น + กราฟ
- Scheduler งานครบกำหนด/เลยกำหนด + reply แนบรายการ + สรุปรายสัปดาห์
- (optional) LLM fallback, PostGIS ตำบล

### เฟส 4 — Production
- ย้ายขึ้น VPS (เปิด 24 ชม.), backup Postgres รายวัน, monitoring, log

## E. ความเสี่ยง & วิธีลด

| ความเสี่ยง | ลดด้วย |
|---|---|
| เซลล์พิมพ์ไม่ตาม template | พจนานุกรมคำพ้อง + bot บอกช่องที่ขาด + LLM fallback + คิวรอตรวจ |
| follow-up ผูกผิดงาน | ใช้ "ตอบกลับ"/รหัสงานเป็นหลัก, เบอร์+geo เป็นรอง, ไม่ชัวร์ → รอตรวจ |
| ข้อมูลซ้ำ | unique webhookEventId, hash ข้อความ, geo radius, merge site |
| รูปหายจาก LINE | ดาวน์โหลดทันที + retry queue |
| เครื่อง local ดับ | redelivery + ย้ายขึ้นเซิร์ฟเวอร์จริงก่อนใช้งานเต็ม |
| bot ถูกเตะออกจากกลุ่ม | จับ `leave` event → แจ้งเตือนแอดมิน |
| โควต้าข้อความ Free | ใช้ reply (ฟรี) เป็นหลัก, push เฉพาะสรุปรายสัปดาห์ |
